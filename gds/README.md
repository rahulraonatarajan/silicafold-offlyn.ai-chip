# GDS Directory

## Purpose

This directory is for storing references to or summaries of generated GDS artifacts. 

**Do NOT manually create or edit GDS files here.** The authoritative GDS must come from the automated Tiny Tapeout/OpenLane flow via GitHub Actions.

## Where Real GDS Files Come From

1. **GitHub Actions**: The `gds.yml` workflow generates GDS files
2. **Download artifacts**: From the Actions tab after successful workflow run
3. **Extract**: The GDS file will be in `runs/wokwi/results/final/gds/`

## What You Might Store Here

- Links to artifact downloads
- Checksums of verified GDS files
- Notes about successful builds
- Version tracking information

## What NOT to Store Here

- Hand-created GDS files
- Modified GDS files
- Large binary files (use Git LFS or external storage)
- Unverified outputs

## Verification

Before considering any GDS file as valid:

1. Confirm it was generated by the official workflow
2. Check DRC report shows zero violations
3. Check LVS report shows match
4. Verify timing closure
5. Review synthesis warnings

## Viewing GDS

To view GDS files, use:
- [KLayout](https://www.klayout.de/) - Free, open-source
- Magic VLSI - Open-source
- Commercial tools (Cadence, Synopsys)
